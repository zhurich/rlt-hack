# Метрика качества подбора (шаг 3)

## Схема проверки

- История — все лоты по дату отсечки включительно; проверяемые лоты — случайная выборка
  после неё. Участники проверяемых лотов системе не видны.
- Для каждого проверяемого лота история обрезана по дате отсечки, а не по дню публикации
  лота: система не знает ничего, что случилось после отсечки. Это строже, чем в работе.
- Истина — реальные участники лота (ЭМ) или исполнитель (АИС ГЗ, там участник один).
  Физлица-преподаватели из истины исключены: их система не рекомендует.
- Веса подбирались на одном периоде, итог считается на следующем:
  настройка — история по 2025-08-31, лоты сентября–октября 2025;
  проверка — история по 2025-10-31, лоты ноября–декабря 2025.
- Метрики: Recall@10 — доля реальных участников в первой десятке; «победитель в топ-10» —
  доля лотов, где победитель попал в десятку; MAP@10 — учитывает порядок внутри десятки.

Воспроизведение: `python scripts/evaluate.py 6000` (итог), `python scripts/tune.py --sim-power 4
--win-bonus 1.5` (подбор весов и таблица факторов), `python scripts/tune_sweep.py` (перебор
параметров).

## Итог

Полный подбор, 5 923 лота ноября–декабря 2025, 34 мс на лот:

| Срез | Лотов | Recall@10 | Победитель в топ-10 | MAP@10 |
|---|---|---|---|---|
| Все | 5 923 | 0,656 | 0,671 | 0,447 |
| ЭМ | 3 422 | 0,657 | 0,683 | 0,456 |
| АИС ГЗ | 2 501 | 0,656 | 0,656 | 0,435 |

Выбор идёт из 44 тыс. поставщиков; десять самых активных поставщиков дают Recall@10 = 0,048.

## Вклад факторов

Что теряется, если убрать один фактор из итогового варианта (Recall@10 / MAP@10):

| Без фактора | Recall@10 | MAP@10 |
|---|---|---|
| текст (участие в похожих лотах) | 0,474 | 0,287 |
| история с заказчиком | 0,646 | 0,431 |
| полный код ОКПД2 | 0,648 | 0,446 |
| площадка | 0,656 | 0,441 |
| цена | 0,658 | 0,448 |
| СМП | 0,658 | 0,448 |
| специализация | 0,660 | 0,450 |
| ОКПД2: категория, группа, класс | 0,660 | 0,450 |
| регион | 0,660 | 0,450 |

- Основной фактор — текст: поставщики, участвовавшие в лотах с похожим предметом и позициями.
- ОКПД2 поверх текста почти ничего не добавляет: похожие по тексту лоты и так лежат в том
  же коде, а внутри кода текст различает точнее.
- Регион бесполезен для ранжирования: почти все поставщики и заказчики петербургские.
- Ручные веса шага 2 переоценивали ОКПД2 и проигрывали даже одному тексту.

## Параметры признаков

Перебор (каждый вариант — с заново подобранными весами), Recall@10 на настройке / проверке:

| Вариант | Настройка | Проверка |
|---|---|---|
| исходные (300 лотов, близость², победа ×1,5, полураспад 365 дн.) | 0,583 | 0,649 |
| 1000 похожих лотов | 0,568 | 0,645 |
| 100 похожих лотов | 0,582 | 0,654 |
| близость в 4-й степени | 0,590 | 0,659 |
| близость в 1-й степени | 0,576 | 0,650 |
| полураспад 180 дней | 0,582 | 0,649 |
| полураспад 730 дней | 0,581 | 0,644 |
| победа без надбавки | 0,571 | 0,645 |
| победа ×2,5 | 0,590 | 0,659 |
| **близость⁴ + победа ×2,5 (принято)** | **0,587** | **0,660** |

Разброс между вариантами — около 0,01, это на уровне шума выборки (стандартная ошибка
Recall@10 на 2–3 тыс. лотов ≈ 0,008). Параметры выбраны по периоду настройки; дальнейшая
подкрутка весов заметного прироста не даст — нужны новые признаки или данные.

## Оговорки

- На периоде настройки цифры ниже (0,587 против 0,660): сентябрь–октябрь и ноябрь–декабрь
  отличаются составом закупок, а у проверки на два месяца больше истории.
- В АИС ГЗ известен только исполнитель, поэтому Recall@10 там — это «исполнитель в десятке».
- Метрика считает ошибкой рекомендацию подходящего поставщика, который в лоте не участвовал.
  Для расширения конкуренции такие рекомендации как раз полезны, так что реальное качество
  выше, чем показывает Recall.
