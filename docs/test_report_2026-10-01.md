# Отчёт о тестировании сервиса

Дата: 01.10.2026

## Итог

Сборка Python-модулей и проверка типов фронтенда проходят. API и пользовательские сценарии работают на подготовленной базе: демо-лоты отвечают примерно за 250–350 мс, новая закупка — за 190–350 мс. При этом обнаружен существенный дефект временной отсечки: для исторического лота ранжирование использует агрегаты поставщиков, посчитанные по всему периоду данных, включая события после даты лота. На одном демо-кейсе из-за этого меняется первое место. Это противоречит заявлению интерфейса, что подбор видит только историю до даты закупки.

## Найденные дефекты

### P1. История после даты закупки влияет на историческое ранжирование

В `Recommender.__init__` профили по умолчанию строятся до максимальной даты в базе (`recsys/recommender.py:75–104`). При скоринге исторического лота дата ограничивает часть признаков, но профили цены, площадки, СМП и общий знаменатель специализации остаются рассчитанными по всему периоду (`recsys/recommender.py:215–222`). Они участвуют в итоговом балле.

**Воспроизведение:** открыть демо-лот `6019464` (дата публикации 16.12.2025) в обычном сервисе, затем сравнить результат с тем же лотом при построении профилей только по данным до 15.12.2025. В обычном режиме первое место занимает ИНН `7810411428`; при временно ограниченных профилях — `7839135474`. В двух из семи демо-лотов обнаружена перестановка мест в топ-15. Максимальное изменение абсолютного балла в демо-кейсах — 3,38.

**Ожидается:** все признаки, влияющие на исторический подбор, используют данные строго до даты запроса (или UI явно помечает текущие агрегаты как актуальные на дату выгрузки и не представляет их частью исторического результата).

### P2. Для исторического лота карточка показывает будущие показатели компании

Сервис дополняет результат карточками из текущей таблицы `companies`, где история сведена за 2024–2025 годы (`recsys/service.py:106–135`). Поэтому интерфейс рядом с историческим результатом показывает показатели позднее даты лота без пометки об этом.

**Воспроизведение:** открыть лот `5964926` от 03.12.2025. Для ООО «ОФИСМАГ СПБ» интерфейс показывает последнюю заявку 30.12.2025 и итоги за весь 2025 год (3 511 побед из 8 276 участий), хотя рядом указано, что подбор видит только историю до даты закупки.

**Ожидается:** либо показывать карточные показатели на дату лота, либо явно разделить «данные для подбора на дату лота» и «актуальные сведения на дату выгрузки».

### P2. API принимает некорректные коды ОКПД2 и отрицательную цену без предупреждения

`POST /api/recommend` не проверяет формат `codes` и диапазон `price` (`app/main.py:48–54`). Отрицательная цена принимается с HTTP 200 и молча не участвует в ценовом факторе; `codes: ["abc"]` также принимается и может дать пустую выдачу. При смеси верного и неверного кода вес верного кода уменьшается из-за равномерной нормализации входного списка.

**Ожидается:** отклонять отрицательную цену и коды, не соответствующие допустимому формату ОКПД2, с понятной ошибкой валидации; не учитывать некорректный код молча.

### P3. В узкой шапке подпись раздела обрезана

При ширине окна браузера около 637 px у навигации остаётся 82 px, а горизонтальная полоса прокрутки скрыта (`web/src/ds/navigation/AppHeader.tsx`, стили `overflowX: 'auto'` и `scrollbarWidth: 'none'`). Подпись «Качество и источники» визуально обрезается до «Качество». Переход с видимой части работает, но назначение раздела не читается полностью и нет явного индикатора прокрутки.

**Ожидается:** адаптивно переносить/сокращать пункты или показывать доступную прокрутку навигации.

## Проверенные сценарии

- Python: `python -m compileall -q app recsys enrich scripts` — успешно.
- Фронтенд: `npm run typecheck` — успешно. `npm run build` остановился на `spawn EPERM` при запуске esbuild в этой среде; это ограничение запуска процесса, поэтому результат полной production-сборки здесь не подтверждён.
- API: `/`, `/api/stats`, `/api/examples`, `/openapi.json`; загрузка лота, поиск по тексту, ввод новой закупки, HTTP-ошибки для отсутствующего лота и неверного JSON.
- Демо: все семь лотов из `DEMO_LOTS` возвращают по 15 поставщиков из истории и 10 новых компаний; ответ 248–347 мс.
- Новая закупка: текст, ОКПД2 `26.30.11`, цена, площадка ЭМ — ответ 349 мс, интерфейс отобразил входные данные и результаты.
- UI: поиск по примеру, новая закупка, карточка компании, экран сравнения; ошибок и предупреждений в консоли браузера не найдено.
- Раздел качества и источников открылся и показал заявленные метрики, объём базы и источники. На узком окне обнаружено визуальное обрезание подписи этого раздела в шапке (P3 выше).
- Метрика: `scripts/evaluate.py 2000` фактически проверил 1 975 лотов (25 выборок исключены, так как после фильтра физлиц не осталось участников): Recall@10 0,660; победитель в топ-10 0,675; MAP@10 0,453; среднее 39 мс на лот. Значения близки к опубликованным в `docs/metrics.md`.
- База: 604 452 извещения, 2 971 651 позиции, 1 010 138 строк участников, 508 184 компании; таблицы обогащения присутствуют. Найдены 21 нулевая цена и 31 дублированная пара лот–поставщик — дубли уже отмечены в разведке данных (`CLAUDE.md`), отдельного сбоя API из-за них не выявлено.

## Ограничения прогона

Порт 8010 уже был занят готовым экземпляром сервиса; поэтому API и UI проверялись на отвечающем экземпляре, а запуск второго экземпляра на том же порту завершился `WinError 10048`. Полная команда `npm run build` не завершилась из-за `spawn EPERM`; статическая проверка типов прошла, а собранная ранее `web/dist` успешно отдалась браузеру. В репозитории отдельного набора автоматических тестов не найдено.
