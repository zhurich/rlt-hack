# Подбор поставщиков для АИС ГЗ и электронного магазина Санкт-Петербурга

Сервис для хакатона RLT.Университет (Росэлторг, Санкт-Петербург, 1–2 октября 2026).
На входе — закупка (лот из истории или описание новой), на выходе — ранжированный список
поставщиков, производителей и дистрибьюторов с ролью, статусом и объяснением, почему каждый
рекомендован.

Развёрнутый экземпляр: <http://103.88.241.174:8010/>
(сразу с примером — <http://103.88.241.174:8010/#lot=5964926>).

## Что умеет

- **Подбор по лоту из истории.** По номеру лота или словам из предмета закупки. Подбор видит
  только историю до даты лота, поэтому рядом показано, на каких местах в выдаче оказались
  реальные участники и победитель.
- **Подбор для новой закупки.** По тексту, кодам ОКПД2, цене, площадке и признаку «для СМП».
  Если коды не указаны, сервис определяет их по похожим закупкам.
- **Два списка.** Поставщики из истории закупок и отдельно — новые компании из открытых
  реестров, которые в этих закупках ещё не участвовали.
- **Роль и статус у каждой компании** с обоснованием и источником.
- **Объяснение.** Причины человеческим языком и разбивка балла по факторам — из тех же чисел,
  по которым считается балл.
- **Карточка компании, сравнение нескольких компаний, экран «Качество и источники».**
- Страница работает и на телефоне.

Подбор отвечает за 0,2–0,4 с. Внешних запросов и нейросетей в работающем сервисе нет: всё
считается на локальных индексах, построенных заранее.

## Как это работает

### Подбор поставщиков из истории

Итоговый балл = релевантность × (1 + надбавки).

Релевантность складывается из взвешенного числа заявок поставщика:

- в закупках с похожим предметом (TF-IDF по текстам лотов, основной фактор);
- по тем же кодам ОКПД2 на четырёх уровнях иерархии (класс, группа, вид, полный код);
- у того же заказчика.

Свежие заявки весят больше старых (вдвое меньше за год), победа — больше, чем участие.

Надбавки: попадание в привычный для поставщика ценовой диапазон, специализация на этой
категории, работа на той же площадке (АИС ГЗ или электронный магазин), победы в закупках
для СМП.

Все признаки считаются в момент запроса и только по истории строго раньше дня закупки.
Веса подобраны на лотах сентября–октября 2025 и проверены на ноябре–декабре.
Физлица-преподаватели (12-значные ИНН в классе 85) из выдачи исключены: это не рынок.

### Новые компании

Отдельный список — компании Санкт-Петербурга и Ленинградской области из реестра МСП,
которых в истории закупок нет. Подбираются по связи «ОКВЭД компании → ОКПД2 закупки»,
выученной на истории, по совпадению ОКВЭД, тексту и признакам достоверности.
Способ и его проверка описаны в [docs/enrichment.md](docs/enrichment.md).

### Обогащение

Выполняется заранее, не в момент запроса. У каждой записи зафиксирован источник.

| Источник | Что берётся |
|---|---|
| Единый реестр субъектов МСП (ФНС) | название, ОКВЭД, категория, дата включения, лицензии |
| Среднесписочная численность (ФНС) | число работников |
| Доходы и расходы (ФНС) | выручка за 2025 год |
| Задолженность по налогам (ФНС) | сумма недоимки |
| Реестр недобросовестных поставщиков (ЕИС) | факт включения |

### Роль

Определяется правилами по основному ОКВЭД: классы 01–32 — производитель; 46 и 45 (кроме
45.2) — дистрибьютор; остальные — поставщик.

### Статус

Отвечает на вопрос «насколько контрагент проверен». Правила применяются сверху вниз:

| Статус | Правило |
|---|---|
| риск | есть запись в реестре недобросовестных поставщиков |
| требует проверки | налоговый долг больше 100 тыс. ₽ либо юрлицо из истории не найдено в реестрах |
| проверенный | участвовал в закупках, 3 победы и больше |
| участник | участвовал в закупках, побед меньше 3 |
| новый, подтверждён | в закупках не участвовал; есть выручка за 2025 год и больше двух лет в реестре МСП |
| новый | в закупках не участвовал; найден в реестре МСП |

Подробнее — [docs/statuses.md](docs/statuses.md).

## Стек

Python 3.14, FastAPI, DuckDB, NumPy/SciPy, scikit-learn (TF-IDF). Фронт — React + TypeScript
(strict) + Vite, одна страница; шрифты и иконки вшиты в сборку.

## Структура репозитория

    app/main.py            API и раздача собранной страницы
    recsys/build.py        предрасчёт индекса подбора → data/index.pkl
    recsys/recommender.py  подбор поставщиков из истории (признаки, веса, балл)
    recsys/pool.py         подбор новых компаний → data/pool.pkl
    recsys/explain.py      причины и разбивка балла
    recsys/service.py      полный ответ: подбор + карточки + статусы + объяснения
    enrich/                загрузка реестров и сборка справочника компаний
    scripts/               загрузка CSV, разведка, метрика, подбор весов
    web/                   фронт (web/src/ds — дизайн-система, web/src/screens — экраны)
    docs/                  разведка данных, метрика, обогащение, статусы, сценарий защиты
    data/                  данные и индексы (в git не попадают)

## Запуск локально

Нужны Python 3.14 и Node.js 20.

    python -m venv .venv
    .venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
    pip install -r requirements.txt

### Данные и индексы

Исходные файлы организаторов кладутся в `data/raw/` под именами `notices.csv`, `tru.csv`,
`suppliers.csv` (CSV, UTF-8, разделитель `;`). Дальше по порядку:

    python scripts/load.py        # CSV → data/rlt.duckdb
    python -m recsys.build        # индекс подбора → data/index.pkl, ~40 с

    python -m enrich.rmsp         # реестр МСП (архив data/ext/rsmp.zip, 2 ГБ)
    python -m enrich.fns          # численность, доходы, задолженность
    python -m enrich.rnp          # РНП из ЕИС, ~8 мин
    python -m enrich.companies    # справочник компаний, роли, статусы
    python -m recsys.pool         # пул новых компаний → data/pool.pkl

Архивы ФНС скачиваются вручную в `data/ext/`; ссылки — в начале каждого модуля `enrich/`.
Пока идёт обогащение, базу читать нельзя: DuckDB однопользовательская на запись.

Если есть готовые `data/index.pkl`, `data/pool.pkl` и `data/rlt.duckdb`, этот раздел
пропускается.

### Сервис и страница

    cd web && npm install && npm run build && cd ..
    python -m uvicorn app.main:app --port 8010

Страница — <http://127.0.0.1:8010/>. Для разработки фронта — `npm run dev` в `web/`
(запросы `/api` проксируются на порт 8010).

## Развёртывание в Docker

    git clone https://github.com/zhurich/rlt-hack.git && cd rlt-hack
    mkdir -p data      # сюда скопировать index.pkl, pool.pkl, rlt.duckdb (~685 МБ)
    docker compose up -d --build

Данные в образ не входят и монтируются только на чтение. Нужно около 2 ГБ памяти.
Обновление и разбор ошибок — в [docs/deploy.md](docs/deploy.md).

## API

| Запрос | Что делает |
|---|---|
| `GET /api/lot/{lot_id}` | подбор по лоту из истории |
| `POST /api/recommend` | подбор для новой закупки |
| `GET /api/search?q=` | поиск лотов в истории по тексту |
| `GET /api/examples` | лоты-примеры |
| `GET /api/stats` | объём базы, метрика, источники |

Описание схемы — на `/docs` работающего сервиса. Пример:

    curl -X POST http://127.0.0.1:8010/api/recommend \
      -H "Content-Type: application/json" \
      -d '{"text": "поставка бумаги для офисной техники А4", "codes": ["17.12.14"], "price": 300000, "source": "ЭМ"}'

В ответе: закупка, определённые коды ОКПД2, `items` — поставщики из истории, `new_items` —
новые компании. У каждого элемента — балл, карточка компании с ролью и статусом, причины,
разбивка балла по факторам и похожие закупки с его участием.

## Проверка качества

    python scripts/evaluate.py 6000       # Recall@10, победитель в топ-10, MAP@10
    python scripts/try_lot.py 5964926     # подбор по лоту в консоли, с местами реальных участников
    python scripts/tune.py                # подбор весов и таблица вклада факторов
    python scripts/validate_pool.py       # проверка подбора новых компаний

## Соответствие условиям хакатона

- Внешние API нейросетей в работающей системе не используются.
- Ответ — доли секунды: индексы и справочник компаний посчитаны заранее.
- Обогащение — офлайн, источник указан у каждой записи.

## Что не сделано

- Реестр промышленной продукции Минпромторга (ГИСП) не подключён: сайт закрыт от
  автоматических запросов, нужна ручная выгрузка.
- РНП по 44-ФЗ неполон: поиск ЕИС отдаёт не больше 5 000 записей на запрос.
- Статус не учитывает сведения ЕГРЮЛ (ликвидация, реорганизация).
- Карточка компании показывает сведения на дату выгрузки, а не на дату лота.
- `POST /api/recommend` не проверяет формат кодов ОКПД2 и знак цены.
